# Native macOS openXC7 for Arty A7-35T

The pipeline is Spade/Swim → SystemVerilog → Yosys → nextpnr-xilinx → Project
X-Ray → SRAM bitstream. No Spadeforge or Vivado installation is required.
See the [SD project](../../projects/microsd-emulator/README.md) for board use,
and its [DDR guide](../../projects/microsd-emulator/ddr/README.md) for generator
prerequisites and the complete build command.

## Toolchain build

Tested on macOS 26.6.2 arm64 with Apple Clang 21.0.0, CMake 3.30.2,
Boost 1.90.0, Eigen 5.0.1, Homebrew Flex 2.6.4, and Python 3.11.9.
Only Eigen and Flex needed to be installed with Homebrew on this machine.
The SD frontend uses negative-edge slice registers and additionally requires
[`nextpnr-negative-edge-timing.patch`](nextpnr-negative-edge-timing.patch): upstream 0.9.4 otherwise reports every register as rising-edge, missing half-cycle
timing paths. This patch fixes edge classification; the timing model remains
an estimate rather than vendor timing signoff.

To install, clone these revisions and run the following with absolute `SOURCE`
and `PREFIX` paths. The scripts expect this prefix by default:

```sh
# Run from the repository root; SOURCE contains the checked-out repositories.
SOURCE=/private/tmp/openxc7-macos
PREFIX="$PWD/gateware/build/openxc7-macos"

# Prerequisites, if missing:
brew install cmake ninja boost eigen flex bison python@3.11 uv

# On a fresh installation, populate SOURCE (skip these clones if already present).
mkdir -p "$SOURCE"
git clone https://github.com/openXC7/nextpnr-xilinx.git "$SOURCE/nextpnr-xilinx"
git -C "$SOURCE/nextpnr-xilinx" checkout ece39e171b03180c0efd6ba024ef175ce3ad0aad
git -C "$SOURCE/nextpnr-xilinx" submodule update --init \
  xilinx/external/prjxray-db xilinx/external/nextpnr-xilinx-meta
git clone https://github.com/YosysHQ/yosys.git "$SOURCE/yosys"
git -C "$SOURCE/yosys" checkout 435977e97008578a4532da60e70f75b5e88d076d
git -C "$SOURCE/yosys" submodule update --init --recursive
git clone https://github.com/openXC7/prjxray.git "$SOURCE/prjxray"
git -C "$SOURCE/prjxray" checkout 57c33a1f88ec6b5c4dc37f05bd760210a6fe9e15
git -C "$SOURCE/prjxray" submodule update --init --recursive

git -C "$SOURCE/nextpnr-xilinx" apply "$PWD/gateware/experiments/openxc7-macos/nextpnr-negative-edge-timing.patch"

cmake -S "$SOURCE/nextpnr-xilinx" -B "$SOURCE/nextpnr-xilinx/build" -G Ninja \
  -DARCH=xilinx -DBUILD_PYTHON=OFF -DBUILD_GUI=OFF -DUSE_OPENMP=OFF
cmake --build "$SOURCE/nextpnr-xilinx/build" -j 8
python3 "$SOURCE/nextpnr-xilinx/xilinx/python/bbaexport.py" \
  --device xc7a35tcsg324-1 --bba "$SOURCE/xc7a35tcsg324.bba"
"$SOURCE/nextpnr-xilinx/build/bbasm" --l \
  "$SOURCE/xc7a35tcsg324.bba" "$SOURCE/xc7a35tcsg324.bin"

cmake -S "$SOURCE/yosys" -B "$SOURCE/yosys/build" -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX="$PREFIX" \
  -DYOSYS_USE_BUNDLED_LIBS=ON -DYOSYS_WITHOUT_SLANG=ON \
  -DYOSYS_WITHOUT_TCL=ON -DYOSYS_ENABLE_UNIT_TESTS=OFF \
  -DFLEX_EXECUTABLE=/opt/homebrew/opt/flex/bin/flex
cmake --build "$SOURCE/yosys/build" -j 8
cmake --install "$SOURCE/yosys/build"

cmake -S "$SOURCE/prjxray" -B "$SOURCE/prjxray/build" -G Ninja \
  -DCMAKE_BUILD_TYPE=Release
cmake --build "$SOURCE/prjxray/build" --target xc7frames2bit bitread -j 6

mkdir -p "$PREFIX/bin" "$PREFIX/libexec" \
  "$PREFIX/share/nextpnr" "$PREFIX/share/prjxray"
cp "$SOURCE/nextpnr-xilinx/build/nextpnr-xilinx" \
  "$SOURCE/nextpnr-xilinx/build/bbasm" \
  "$SOURCE/prjxray/build/tools/xc7frames2bit" \
  "$SOURCE/prjxray/build/tools/bitread" "$PREFIX/bin/"
cp "$SOURCE/xc7a35tcsg324.bin" "$PREFIX/share/nextpnr/"
cp -R "$SOURCE/nextpnr-xilinx/xilinx/external/prjxray-db/artix7" \
  "$PREFIX/share/prjxray/"
cp "$SOURCE/prjxray/utils/fasm2frames.py" "$PREFIX/libexec/"
uv venv --python /opt/homebrew/bin/python3.11 "$PREFIX/venv"
uv pip install --python "$PREFIX/venv/bin/python" "$SOURCE/prjxray"
```

`USE_OPENMP=OFF` avoids the upstream default `-fopenmp` flag, which Apple
Clang rejects. Explicit Homebrew Flex avoids incompatible lexer method
signatures generated by Apple's `/usr/bin/flex`. Disabling Tcl and Slang
keeps the Yosys build focused on the Verilog frontend used here.

The copied `fasm2frames.py` entry point avoids sourcing X-Ray's Vivado-oriented
environment setup. Its dependencies are installed in an isolated virtual
environment. The installed binaries dynamically depend on Homebrew libraries;
this is a local installation, not a redistributable standalone bundle.

## Validation and artifacts

`build_probe.py` creates an input-only pin tester. `build_emulator.py` creates
the read-only BRAM stage. `build_ddr.py` creates the DDR-backed card.
Use `--help` for each script's profiles and output options. Outputs live under
`gateware/build/` and are intentionally not committed.

The negative-edge patch is mandatory for the fast frontend: it makes the
router account for half-cycle paths. The build runs a timing probe to detect
an unpatched binary. Passing nextpnr estimates is not vendor timing signoff;
retain routed reports and repeat host integrity tests after programming.

The locked simulation dependency Cocotb 1.9.2 can fail to compile with newer
Apple linkers (`unsupported mach-o filetype`). The extraction was tested using
the existing working local Cocotb installation; Linux CI installs from the
lockfile. Do not treat this Python installation failure as a gateware failure.

If an older native nextpnr binary fails at startup with a missing Boost symbol
after a Homebrew upgrade, rebuild it against the installed Boost version (or
use the exact compatible libraries from its original build). This is a loader
failure, not a gateware timing failure. The negative-edge preflight must pass
before using its timing reports.
